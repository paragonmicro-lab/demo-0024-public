    Demo 1b: VMware to both OpenShift clusters¶

    Version 0.4.1 · draft · 2026-10-12 · class/demos/01b-vmware-to-both-sites.md

    What you will learn¶

    You migrate one VMware VM to two different OpenShift clusters, first site A and then site B, using the Migration Toolkit for Virtualization (MTV) installed on each. You do it twice: once from the command line (you build the Plan and Migration objects) and once in the console, where the lab has staged your site B plan and your task is to review it and start it. That shows the console is a front end to the same objects. At each landing you prove the database arrived intact and that the VMware Tools were replaced by the OpenShift guest agent. CI runs exactly these command-line steps (action=test-migration, automation/test/migrate_both.sh), so a green CI run means they work on this booking.

    Picture: lab diagram. The rule for this demo: only one copy of your VM may run on the VLAN at a time. The bridge map keeps the VM's own address, so a second running copy would collide. Stop each copy before the next move. Because every copy keeps $VM_IP, the helpers work unchanged on both sites, and Toolkit T.4 is not needed.

    Already ran Demo 1? Then your VM is already on site A (named $VM in your namespace $VMNS). Skip 1b.2, stop that copy (one copy on the VLAN), power the vSphere original back on, and go straight to 1b.3.

    🖥️ Where you type the commands: your browser terminal. Every bash block in this guide runs in your own terminal pod, in the browser: in the site A console, project <your class ID> → Workloads → Pods → sql-client → Terminal (Toolkit T.1). Nothing is installed on your computer. It already knows your VM and its address (type ovedr); dblogin and oclogin (Toolkit T.1-T.2) stay signed in while the pod runs. Variables you export last until you close that Terminal tab: if you reopen it, re-run the guide's export lines. Paste with right-click → Paste (or Ctrl+Shift+V / ⌘V). powershell blocks run inside your Windows VM, from its console (vCenter Launch Web Console, or the VM's Console tab in OpenShift).

    1b.1 Inject before you move¶

    🎬 1b.1 Inject before you move: a recording of this whole section, done in the console (placeholder until recorded: class/.images/01b-1b-1-inject-before-move.mp4).

    mark d1b-before                        # your row, over the network, to the VM still on vSphere
verify                                 # chain_ok = t
export FP=$(sql -Atc "SELECT fingerprint FROM ovedr_checksum()"); echo "fingerprint before: $FP"

    In the VM (vCenter → your VM → Launch Web Console, as .\student-NN):

    Add-Content "C:\Users\Public\ovedr\$env:USERNAME.txt" "$(Get-Date -Format o)  d1b-before (vSphere)"

    1b.2 To site A, from the command line (you build the plan)¶

    🎬 1b.2 To site A, from the command line (you build the plan): a recording of this whole section, done in the console (placeholder until recorded: class/.images/01b-1b-2-site-a-command-line-build-plan.mp4).

    How each object is built, field by field: Lab S §S.8 and §S.12. Red Hat: Creating and running a migration plan from the CLI [verify link].

    CTX=site-a; SLOT=$A; PLAN="d1b-$VM-to-${SLOT}"; PROV="ovedr-vcenter0$N"
oc --context $CTX -n openshift-mtv get provider "$PROV" \
  -o jsonpath='{.status.conditions[?(@.type=="Ready")].status}{"\n"}'          # True
oc --context $CTX -n openshift-mtv get networkmap "$PROV-net-bridge" >/dev/null && NET="$PROV-net-bridge" || NET="$PROV-net"
echo "plan=$PLAN network-map=$NET"

oc --context $CTX apply -f - <<YAML
apiVersion: forklift.konveyor.io/v1beta1
kind: Plan
metadata: { name: $PLAN, namespace: openshift-mtv }
spec:
  warm: false
  targetNamespace: $VMNS
  provider:
    source:      { name: $PROV, namespace: openshift-mtv }
    destination: { name: host,  namespace: openshift-mtv }
  map:
    network: { name: $NET,          namespace: openshift-mtv }
    storage: { name: $PROV-storage, namespace: openshift-mtv }
  vms: [ { name: $VM } ]
YAML
oc --context $CTX -n openshift-mtv wait plan/$PLAN --for=condition=Ready --timeout=15m       # MTV found your VM

    Start it, then watch:

    oc --context $CTX apply -f - <<YAML
apiVersion: forklift.konveyor.io/v1beta1
kind: Migration
metadata: { name: $PLAN, namespace: openshift-mtv }
spec: { plan: { name: $PLAN, namespace: openshift-mtv } }
YAML
watch -n 20 "oc --context $CTX -n openshift-mtv get migration $PLAN \
  -o jsonpath='{range .status.vms[*].pipeline[*]}{.name}{\"\\t\"}{.phase}{\"\\t\"}{.progress.completed}/{.progress.total}{\"\\n\"}{end}'"
oc --context $CTX -n openshift-mtv wait plan/$PLAN --for=condition=Succeeded --timeout=90m

    The pipeline runs Initialize → DiskTransfer (3 disks) → ImageConversion (virt-v2v: virtio drivers in, VMware Tools out) → VirtualMachineCreation. Then start the VM, if MTV left it stopped:

    oc --context $CTX -n "$VMNS" patch vm $VM --type merge -p '{"spec":{"runStrategy":"Always"}}'   # or: virtctl start $VM
oc --context $CTX -n "$VMNS" wait vmi/$VM --for=jsonpath='{.status.phase}'=Running --timeout=15m
oc --context $CTX -n "$VMNS" get vmi $VM \
  -o jsonpath='{.status.nodeName}{"  agent="}{.status.conditions[?(@.type=="AgentConnected")].status}{"\n"}'

    Check on site A¶

    alive                                  # heartbeat live again (staleness < 10 s), postgres_started is new
verify                                 # chain_ok = t, your d1b-before row is there
sql -Atc "SELECT fingerprint FROM ovedr_checksum()"            # = $FP: every mark arrived, unchanged
mark d1b-after-site-a

    In the VM (Virtualization → VirtualMachines → your VM → Console): read the file back, then add a line:

    Get-Content "C:\Users\Public\ovedr\$env:USERNAME.txt"
Add-Content "C:\Users\Public\ovedr\$env:USERNAME.txt" "$(Get-Date -Format o)  d1b-after (site A)"

    ✍️ Row 1b.A: migration minutes, heartbeat gap, chain_ok, fingerprint equal (yes/no).

    Stop this copy before the next move (one copy on the VLAN at a time):

    oc --context site-a -n "$VMNS" patch vm $VM --type merge -p '{"spec":{"runStrategy":"Halted"}}'   # or: virtctl stop $VM

    1b.3 To site B, in the console (your plan is staged: review it, then start it)¶

    🎬 1b.3 To site B, in the console (your plan is staged: review it, then start it): a recording of this whole section, done in the console (placeholder until recorded: class/.images/01b-1b-3-site-b-console-plan-staged-review-start.mp4).

    MTV powered your source VM off on vSphere. Power it back on first (vCenter → your VM → Power On). MTV copies a VM in the power state it finds it in.

    📸 01b-vsphere-power-on: vCenter, your VM powered on again after the site A move.

    Site B console (https://console-openshift-console.apps.<B>.demo.lab-paragonmicro.com, SSO). The lab staged your plan d1b-<your VM>-to-<B>; it is Ready and not started. Review it screen by screen; the last step, Start, is yours. (To build it yourself instead, use Create plan with the values below and a different name, and start only one of the two.)

    1. Migration for Virtualization → Migration plans → your plan d1b-<your VM>-to-<B>. 📸 01b-ui-plans-list: the Plans page on site B, your staged plan Ready, not started.
    2. Source provider ovedr-vcenter0<N>; Virtual machines tab: your VM only. 📸 01b-ui-select-vm: the plan's VM list with your VM.
    3. Target provider host; target namespace your own, <your class ID> ($VMNS). 📸 01b-ui-plan-details: the plan's details: target provider and namespace.
    4. Network map ovedr-vcenter0<N>-net-bridge (your VM's VLAN, so it keeps its address); storage map ovedr-vcenter0<N>-storage (datastore → nfs-csi on site B). 📸 01b-ui-maps: both maps on the plan.
    5. Migration type: Cold. Your task: Start → confirm. 📸 01b-ui-plan-ready: the plan page showing Ready, with the Start button.
    6. Watch the pipeline: Initialize → DiskTransfer → ImageConversion → VirtualMachineCreation. 📸 01b-ui-pipeline: the migration in progress, with disk transfer percentages. 📸 01b-ui-succeeded: the plan Succeeded.
    7. Virtualization → VirtualMachines → your VM → Start (if stopped) → Overview: node, IP and guest agent. 📸 01b-ui-vm-overview: your VM Running on site B, with Guest agent: connected.

    The same, from the command line (review, then start the staged plan; CI's test runs 1b.2's full build):

    CTX=site-b; SLOT=$B; PLAN="d1b-$VM-to-${SLOT}"
oc --context $CTX -n openshift-mtv get plan "$PLAN" \
  -o jsonpath='{.spec.map.network.name}{"  "}{.spec.map.storage.name}{"  ready="}{.status.conditions[?(@.type=="Ready")].status}{"\n"}'
oc --context $CTX apply -f - <<YAML
apiVersion: forklift.konveyor.io/v1beta1
kind: Migration
metadata: { name: $PLAN, namespace: openshift-mtv }
spec: { plan: { name: $PLAN, namespace: openshift-mtv } }
YAML
oc --context $CTX -n openshift-mtv wait plan/$PLAN --for=condition=Succeeded --timeout=90m
oc --context $CTX -n "$VMNS" patch vm $VM --type merge -p '{"spec":{"runStrategy":"Always"}}'
oc --context $CTX -n "$VMNS" wait vmi/$VM --for=jsonpath='{.status.phase}'=Running --timeout=15m

    Check on site B¶

    alive
verify                                 # d1b-before is there; d1b-after-site-a is NOT (that row lives only in the site A copy)
sql -Atc "SELECT fingerprint FROM ovedr_checksum()"            # = $FP again
mark d1b-after-site-b

    💡 Why is d1b-after-site-a missing on B? Both migrations copied the VM from vSphere, and the site A copy added that row after its own move. Two migrations of one source give two independent copies. To carry site A's changes to B, you move the VM from A to B (Demo 3), or replicate it (Demo 4).

    ✍️ Row 1b.B: the same measurements on site B.

    📸 01b-ui-console-file: the site B VM console showing your file, with the vSphere and site A lines in it.

    1b.4 Clean up (your copies only)¶

    🎬 1b.4 Clean up (your copies only): a recording of this whole section, done in the console (placeholder until recorded: class/.images/01b-1b-4-clean-up-copies-only.mp4).

    oc --context site-b -n "$VMNS" patch vm $VM --type merge -p '{"spec":{"runStrategy":"Halted"}}'
# Keep the copies for Demo 3, or delete them (their disks go with them):
#   oc --context site-a -n "$VMNS" delete vm $VM ;  oc --context site-b -n "$VMNS" delete vm $VM
oc --context site-a -n openshift-mtv delete migration,plan "d1b-$VM-to-$A" --ignore-not-found
oc --context site-b -n openshift-mtv delete migration,plan "d1b-$VM-to-$B" --ignore-not-found
