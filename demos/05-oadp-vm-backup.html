    Demo 5 (bonus): Back up and restore your VM with OADP¶

    Version 0.2.1 · framework · 2026-10-12 · class/demos/05-oadp-vm-backup.md

    🚧 Bonus, framework. OADP is now built by the lab when a class books it (option backup: oadp, the default for this class). The commands below are unproven [verify] until a booking has run them. Ask your instructor whether your lab has OADP before you start.

    What you will learn¶

    Disaster recovery (Demo 4) keeps a running copy on another site. A backup is different: a point-in-time copy you can restore after a mistake, a bad change or a ransomware event, even when every replica has the damage too. You will back up your whole namespace with OADP (the OpenShift API for Data Protection, Red Hat's Velero-based operator): the VirtualMachine, its disks and its Service. Then you delete it all, restore it, and prove with your own rows that the restored VM holds exactly the data it had at backup time.

    5.1 What a VM backup contains¶

    A backup of your namespace captures its objects (the VirtualMachine, its DataVolumes and PVCs, the Service) and its data: each disk is snapshotted, and the Data Mover copies the snapshot to object storage, so the backup survives even if the cluster's storage is lost. A running Windows VM is backed up crash-consistent unless the guest agent freezes it first: PostgreSQL recovers from that like from a power cut, and your hash chain proves it.

    oc --context site-a -n "$VMNS" get vm,dv,pvc,svc               # what your backup will contain
oc --context site-a -n "$VMNS" get nonadminbackupstoragelocations.oadp.openshift.io 2>/dev/null || echo "(the class's location is the default one)"   # [verify]

    💡 Use full resource names here. On these clusters oc get backup finds ODF's database-backup type and oc get restore finds ACM's, not OADP's. Several operators define a "backup" or "restore". Always write the full name, for example nonadminbackups.oadp.openshift.io or backups.velero.io.

    5.2 Inject before the backup¶

    alive                              # your VM is writing
mark d5-in-backup                  # ✍️ note the id: this row MUST come back
verify                             # chain_ok = t

    In the VM's console (PowerShell):

    Add-Content "C:\Users\Public\ovedr\$env:USERNAME.txt" "$(Get-Date -Format o)  d5-in-backup"

    5.3 Back up your namespace¶

    You create a NonAdminBackup in your own namespace; OADP turns it into a backup of that namespace only. [verify: the NonAdminBackup fields and the student rights on OADP 1.5 (demo-openshift reports what the operator grants)]

    oc --context site-a -n "$VMNS" apply -f - <<EOF
apiVersion: oadp.openshift.io/v1alpha1
kind: NonAdminBackup
metadata: { name: d5 }
spec:
  backupSpec:
    snapshotMoveData: true        # the Data Mover: your disks' data leaves the cluster's storage
    ttl: 24h0m0s
EOF
oc --context site-a -n "$VMNS" get nonadminbackups.oadp.openshift.io d5 -w            # Ctrl-C when its phase is Created and the backup Completed
mark d5-after-backup               # this row is NOT in the backup: it must be gone after the restore

    Console: your project → Operators → Installed Operators → OADP → NonAdminBackup → Create.

    ✍️ Row 5.3: the backup's duration and size (oc -n "$VMNS" get nonadminbackups.oadp.openshift.io d5 -o yaml, under status).

    5.4 Lose it: delete your VM¶

    oc --context site-a -n "$VMNS" delete vm "$VM"                     # the VM and its disks are gone
oc --context site-a -n "$VMNS" get vm,pvc                          # nothing left of your VM
alive                                                              # fails: that is the disaster

    5.5 Restore, and prove the data¶

    oc --context site-a -n "$VMNS" apply -f - <<EOF
apiVersion: oadp.openshift.io/v1alpha1
kind: NonAdminRestore
metadata: { name: d5 }
spec:
  restoreSpec:
    backupName: d5                # your NonAdminBackup   [verify]
EOF
oc --context site-a -n "$VMNS" get nonadminrestores.oadp.openshift.io d5 -w           # Ctrl-C when the restore Completed
oc --context site-a -n "$VMNS" get vm "$VM" -w                      # Running again
until alive >/dev/null 2>&1; do sleep 10; done; alive              # Windows booted, PostgreSQL recovered
verify                                                             # chain_ok = t
sql -c "SELECT stage FROM marks WHERE student = '$ME' AND stage LIKE 'd5-%' ORDER BY id;"

    ✅ d5-in-backup is back and chain_ok = t. d5-after-backup is gone: it was written after the backup, which is exactly what a restore means. Your file in the VM ends at d5-in-backup too.

    ✍️ Row 5.5: the restore's duration, chain_ok, and which of your rows came back.
